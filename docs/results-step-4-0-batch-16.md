# docs/results-step-4-0-batch-16.md — STEP 4-0 배치 16 결과

**범위 확인**: 이 문서는 STEP 4-0 feasibility 검증입니다. production 코드, DB migration, STEP 4-1 작업은 포함하지 않았습니다. 아래 모든 분류(컷 유형/장르/자막 스타일)는 **Claude의 시각적 예비 확인**이며, 사람이 만든 ground truth가 아닙니다. threshold는 영상마다 임의로 조정하지 않았고, 모든 영상에 동일한 규칙(아래 "방법론" 참고)을 적용했습니다.

## 0. 데이터 확인

`manifest.csv`는 16개 샘플(sample_01~16)을 나열하지만, **sample_16.mp4 파일 자체는 실제로 업로드되지 않았습니다**(세션 파일시스템에 존재하지 않음 — 이전에 겪었던 업로드 누락과 같은 유형의 문제로 보입니다). 따라서 이번 배치 분석은 **sample_01~15 (15개)**를 대상으로 했습니다. sample_16(21.5초)이 필요하시면 재업로드를 부탁드립니다.

manifest의 duration/resolution/audio 존재 여부는 ffprobe로 3개 샘플(01, 09, 15)을 무작위 검증해 manifest와 일치함을 확인했습니다. `ffprobe`로 15개 전체의 임베디드 자막 스트림도 확인했는데 **전부 0개**였습니다 — 즉 모든 자막은 burned-in(픽셀 렌더링)이며, 임베디드 트랙을 읽는 방식으로는 우회할 수 없다는 게 이번에도 확인됐습니다.

## 1. 방법론 (모든 영상에 동일하게 적용한 규칙)

- **Scene/visual change**: `scdet=threshold=0:sc_pass=1`로 raw MAFD 신호를 유지한 뒤, `pick_threshold_by_gap.py`로 영상마다 컷 threshold를 데이터 기반으로 골랐습니다. 상위 20개 후보 안에서 25% 이상의 상대적 급락(outlier gap)이 있으면 그 지점을 threshold로 쓰고(`clean_gap`), 없으면 후보 분포의 85퍼센타일을 균일하게 적용합니다(`no_clean_gap_fallback_percentile`). 이건 story_01/game_01에서 수작업으로 했던 것과 같은 로직을 15개 전체에 동일하게 자동 적용한 것입니다 — 영상마다 "보기 좋게" 고른 게 아닙니다.
- **Low-motion/static**: `detect_low_motion.py`(화면 전체 평균 YDIF, ydif_threshold=2.0/window=5s/min_duration=5s — game_01에서 쓴 것과 완전히 같은 고정 파라미터)를 **실패 사례의 기준점**으로 그대로 재사용했습니다. 이 배치의 어떤 영상에도 이 threshold를 새로 맞추지 않았습니다. tile/optical-flow/ssim 등 대안 신호(`analyze_motion_candidates.py`)도 15개 전체에 계산했지만, **ground truth가 없으므로 채점하지 않고 raw 신호만 저장**했습니다(`results/batch/<id>/<id>_motion_signals.csv`).
- **Audio**: `parse_audio_loudness.py`로 영상별 순간 음량(M) 상위 1%를 `candidate_loud_event`, 기존 silencedetect 결과를 `candidate_silence`로만 표시했습니다(모든 영상에 같은 top-1% 규칙 — 절대 dB 기준 아님).
- **Subtitle/자막 존재**: cut 후보 전후 프레임 + 균등 간격 샘플 프레임을 합친 콘택트시트를 영상마다 만들어 Claude가 육안으로 스타일 존재 여부만 분류했습니다. **이건 OCR 정확도가 아니며, ground truth 후보 생성/디버깅/스타일 분류 용도로만 사용했습니다.**
- **Processing time**: 이번 배치는 오디오 필터(silencedetect+volumedetect+ebur128)와 비디오 필터를 **하나의 ffmpeg 패스**로 합친 `run_ffmpeg_signals_batch.sh`를 썼습니다(story_01/game_01은 두 번의 개별 패스였음) — 그래서 이번 비율이 살짝 더 낮게 나오는 것은 실제 처리 효율 차이이지, 다른 방식으로 잰 게 아닙니다(아래 5절에서 설명).

## 3. 장르/편집 스타일별 실패 패턴

**A. 게임 + PIP/얼굴캠 (01, 02, 03)** — game_01과 같은 구조입니다. low-motion baseline이 20.9~53.3%로 game_01의 93%보다는 낮지만, 여전히 사람 확인 없이는 신뢰할 수 없는 수치입니다. 01은 얼굴캠 대신 정적인 VTuber 아바타 그래픽이 있어 game_01과는 다른 종류의 "항상 거의 안 움직이는 인서트" 패턴입니다. 03은 도네이션 알림/KO 그래픽 같은 **오버레이 이펙트가 컷 후보로 오탐될 위험**을 보여주는 가장 뚜렷한 사례였습니다.

**B. 게임, PIP 없음 (11, 13, 14, 15)** — low-motion baseline이 대부분 0~26%로 훨씬 안정적입니다(인서트가 없으니 희석 문제가 덜함). 대신 원래 우려했던 **"게임 자체의 시각효과가 컷으로 오인되는" 문제가 여기서 명확하게 확인**됐습니다 — 14는 스킬 이펙트, 15는 구간 전환 색상변화, 11은 UI 배너 텍스트 변화가 각각 원인입니다. 13(스피드런 원본)은 컷 후보가 1개뿐이라 threshold 방법이 "편집 안 된 원본"과 "많이 편집된 영상"을 어느 정도 구별해낸다는 정성적 신호이기도 합니다.

**C. 길거리 인터뷰 (04, 05, 06)** — 04와 05(단일 연속 인터뷰)는 low-motion baseline이 99.6%, 99.9%로 **이번 배치에서 가장 극단적인 수치**였고, 05는 추가로 **자막/오버레이 그래픽 등장만으로 컷 후보가 오탐되는 새로운 실패모드**를 보여줬습니다. 반대로 06(여러 인터뷰이를 교차편집한 컴필레이션)은 컷 탐지가 아주 깨끗하게 맞았고 low-motion도 51.9%로 상대적으로 덜 극단적입니다 — **같은 "인터뷰" 장르 안에서도 편집 스타일(단일 롱테이크 vs 교차편집 컴필레이션)에 따라 완전히 다른 실패 양상**이 나온다는 것이 이번 배치의 핵심 발견 중 하나입니다.

**D. 빠른 점프컷 몽타주 (07, 08, 09, 10)** — 이 배치에서 가장 결과가 좋았던 그룹입니다. 07/08/10에서 샘플링한 컷 후보는 거의 다 명확한 full_cut이었고, low-motion baseline도 전부 0%로 실제 콘텐츠 특성(계속 장면이 바뀜)과 일치했습니다. 09(레시피)만 비슷한 앵글의 연속 동작이 반복돼 정지화면만으로는 컷 여부 판단이 어려운 needs_human_review 사례가 많을 것으로 예상됩니다.

**E. 단일연속샷 강의/토크 (12)** — 컷이 거의 없고(1개) low-motion baseline이 99.3%입니다. 04/05와 같은 수치 패턴이지만 원인 해석이 다릅니다: 04/05는 "탐지 방식이 이 레이아웃에 안 맞는다"는 결함 쪽에 가깝고, 12는 "이 콘텐츠가 실제로 시각적으로는 계속 정적이지만 내용적으로는 지루하지 않다"는 **정의 자체의 문제**에 가깝습니다. V1에서 "저모션=편집이 필요한 구간"이라는 전제가 이런 장르에는 안 맞을 수 있다는 것을 이번에 명확히 인식했습니다.

## 4. 처리 시간

15개 평균 17.4%, 중앙값 17.5%, 최소 15.2%(sample_12), 최대 20.0%(sample_07) — story_01(21.7%)/game_01(20.6%)보다 전체적으로 낮습니다. 이유는 이번 배치가 오디오 필터(silencedetect+volumedetect+ebur128)와 비디오 필터를 **하나의 ffmpeg 패스**로 합쳤기 때문입니다(1절 방법론 참고) — story_01/game_01은 두 번의 개별 패스를 썼습니다. 즉 **"20~22%" 패턴 자체가 무너진 게 아니라, 두 패스를 하나로 합치면 처리 비용을 더 줄일 수 있다는 실용적인 발견**입니다. 다음 STEP에서 인프라를 설계할 때 필터를 최대한 하나의 패스로 합치는 것을 기본값으로 고려할 근거가 됩니다.

## 5. 오디오

15개 전부 오디오가 존재했고(manifest와 일치), `candidate_loud_event`(영상당 2~8건)와 `candidate_silence`(영상당 0~6건)가 기술적으로 정상 추출됐습니다. **어떤 영상에도 "문제 음량"이라고 단정하지 않았고**, 사람 청취 없이는 전부 `아직 검증 부족` 상태입니다. mean_volume/max_volume은 -23.2~-16.6dB / -6.4~-0.0dB 범위로, 게임/인터뷰/브이로그 장르 간 뚜렷한 패턴 차이는 이 15개만으로는 판단하기 이릅니다.

|---|---|---|
| Scene/visual change 탐지 (raw MAFD + gap threshold) | **아직 검증 부족** | 15개 전부 ground truth 없음. 다만 무편집 원본(13: 후보 1개)과 고편집 몽타주(15: 후보 35개)를 threshold 방법이 정성적으로 잘 구별한 것은 face validity 신호로 기록 |
| Cut vs game_visual_change/visual_effect_non_cut 구분 | **아직 검증 부족** | 14/15/03에서 실제 사례를 확인했지만 사람 확정 없이는 분류 정확도를 낼 수 없음 |
| Low-motion/static (whole-frame baseline) | **제외 후보에 가까움 (비공식)** | game_01(93%)에 이어 04(99.6%)/05(99.9%)/12(99.3%)에서 반복적으로 극단적 오탐 — 다만 공식 판정은 ground truth 없이 내리지 않음, "아직 검증 부족"으로 유지하되 실패 증거는 이미 충분히 누적됨 |
| Low-motion 대안 신호 (tile/optical-flow/ssim) | **아직 검증 부족** | raw 신호만 계산, 채점 안 함(ground truth 없음) |
| 음량 후보 탐지 (candidate_loud_event/silence) | **아직 검증 부족** | 기술적으로 15개 전부 정상 작동 확인, 정확도는 사람 청취 필요 |
| Burned-in 자막 존재/스타일 분류 (Claude 시각) | 검증 대상 아님(디버깅/그라운드트루스 생성 용도) | OCR 정확도로 사용하지 않음. 임베디드 자막 트랙 0건 재확인(ffprobe) |
| OCR 정확도 (실제 엔진) | **아직 검증 부족** | 실제 엔진 미실행, 정책 유지 |
| STT | **아직 검증 부족** | 환경 제약으로 여전히 미실행 |
| 처리시간/비용 | (F1 대상 아님, 측정 완료) | 평균 17.4%, 중앙값 17.5% — 참고용, "20~22%" 패턴은 필터 결합 방식에 따라 더 낮아질 수 있음을 확인 |

## 7. 실패 사례 종합 (숨기지 않음)

1. **PIP/인서트로 인한 low-motion 희석**: game_01에 이어 01/02/03에서도 다양한 정도로 재현됨(20.9~53.3%). 정도는 콘텐츠마다 다름 — 이 배치만으로 일반화하지 않음.
2. **단일연속샷 콘텐츠에서 low-motion baseline의 극단적 오탐**: 04(99.6%)/05(99.9%)/12(99.3%) — PIP가 전혀 없는 콘텐츠에서도 실패가 나타나, 실패 원인이 "PIP 희석"보다 넓다는 것을 이번에 처음 확인함.
3. **자막/오버레이 그래픽 등장이 컷 후보로 오탐됨(신규 발견)**: 05에서 이름표/질문박스 그래픽이 나타나는 순간이 장면 전환 없이도 높은 MAFD를 만듦. 11의 UI 진행 배너 텍스트 변화도 유사한 패턴.
4. **게임 자체 시각효과가 편집 컷과 구별 안 됨(사전 우려의 실증)**: 14(스킬 이펙트), 15(구간 전환 색상변화), 03(도네이션/KO 그래픽 오버레이).
5. **정지화면만으로는 컷 여부 판단이 어려운 콘텐츠(사람도 애매함)**: 09의 연속 요리 동작 — 이건 알고리즘 결함이라기보다 "정지 프레임 비교"라는 검토 방법 자체의 한계로 기록.
6. **저모션(시각적 정적) ≠ 콘텐츠 지루함, 개념적 재검토 필요**: 12에서 확인 — 강의/토크 포맷은 시각적으로 정적이어도 내용은 지루하지 않을 수 있어, "low-motion 구간=편집 필요 구간"이라는 V1 전제 자체를 이 장르에 그대로 적용하면 안 될 수 있음.
7. **오디오 분석이 상대적으로 의미가 약할 수 있는 영상**: 아직 사람이 청취하지 않아 확정할 수 없지만, 04(무음에 가까움 아니지만 조용한 대화 톤 -21.2dB)처럼 다이내믹 레인지가 좁은 콘텐츠는 top-1% 통계적 규칙의 변별력이 약할 가능성이 있음(가설, 검증 전).
8. **sample_16 업로드 누락**: 데이터 파이프라인/업로드 과정의 반복되는 취약점으로 기록(이전 story_01 관련 업로드 누락과 같은 유형).

## 8. 다음 단계 제안 — 전부 라벨링하지 말고 정보량 높은 샘플 우선

16개 전부 사람 라벨링이 필요하지는 않습니다. 아래 4개를 우선 추천합니다(추가 여유가 있으면 5번째도 고려):

1. **sample_05** — 가장 정보량이 높습니다. 단일연속샷 저모션 극단치(99.9%) + 자막발 컷 오탐(신규 발견) 두 가지를 한 영상에서 동시에 검증할 수 있습니다.
2. **sample_02 또는 sample_03** — game_01과 같은 "게임+PIP" 구조라서, **지난번 만들어둔 `evaluate_motion_candidates.py`의 holdout 데이터로 바로 쓸 수 있습니다.** game_01 calibration에서 고정한 threshold를 이 영상에 적용해 실제 holdout F1을 낼 수 있는 좋은 기회입니다(추가 촬영 없이 이미 있는 영상으로 holdout이 가능해짐).
3. **sample_14** — 게임 이펙트-vs-컷 경계를 가장 깨끗하게 보여주는 영상이라, `game_visual_change` 라벨 기준을 확정하는 데 효율적입니다.
4. **sample_06** — 컷 탐지가 잘 맞는 것으로 보이는 긍정 사례를 실제로 검증해, "잘 되는 경우"에 대한 확신도 같이 확보하는 게 좋습니다(실패만 찾다 보면 잘 되는 부분까지 과소평가할 위험).
5. (여유가 있다면) **sample_12** — "저모션≠지루함" 개념 문제를 어떻게 라벨링/처리할지 사용자님의 판단이 필요한 사례입니다.
