# 제품 방향 전환 리서치 — YouTube Planner

작성일: 2026-08-23
범위: 코드 변경 없음. 코드베이스 조사 + 경쟁 분석 + 기술 제약 조사.

---

## 요약 — 먼저 알아야 할 4가지

리서치 결과, **방향 전환의 큰 줄기는 옳습니다.** 다만 근거로 삼으신 차별점 중 일부는 이미 시장에서 사라졌고, 대신 다른 부분이 훨씬 강한 차별점으로 확인됐습니다. 듣기 좋은 말보다 정확한 정보가 필요한 시점이라 솔직하게 적습니다.

1. **"AI가 추천 3개 + 순위 + 이유를 준다"는 이미 경쟁사가 한 달 전에 출시했습니다.**
   TubeBuddy가 **2026년 7월 22일** "Next Video Ideas"를 발표했습니다. 채널 분석 + 시청자 댓글 등 4가지 데이터를 LLM으로 분석해 **영상 아이디어를 근거 강도순으로 순위 매기고, 각 추천의 이유를 설명**합니다. 우리가 생각한 것과 기능 설명이 거의 같습니다.
   → 이걸 제품의 핵심 홍보 문구로 쓰면 안 됩니다.

2. **하지만 "추천 → 결정 → 제작 → 업로드 → 성과 → 다음 추천" 루프 전체를 하는 곳은 정말로 없습니다.**
   TubeBuddy도 vidIQ도 YouTube 자체 기능도, 전부 **아이디어를 "저장"하는 데서 끝납니다.** 저장된 아이디어가 실제 제작 프로젝트로 바뀌고, 체크리스트가 생기고, 업로드되고, 성과가 다시 다음 추천에 반영되는 흐름은 **아무도 만들지 않았습니다.**
   → 여기가 진짜 차별점입니다. 사장님 표현대로 "생성이 아니라 운영"이 맞습니다.

3. **가장 무서운 데이터: Spotter Studio가 이 시장에서 철수했습니다.**
   MrBeast가 테스트하고, "조회수 49% 상승"을 마케팅하던, 훨씬 자금이 많던 회사입니다. 그런데 일반 공개를 중단하고 내부 도구로 전환하면서 여러 차례 정리해고를 했습니다. CEO 발언: 스튜디오를 외부 상품에서 내부 플랫폼으로 전환해 광고·라이선싱 사업에 흡수시킨다는 취지입니다.
   → **"크리에이터용 아이디어 도구"만으로는 사업이 안 된다는 강력한 증거입니다.** 우리가 살아남으려면 운영(ops) 부분이 사업을 지탱해야 합니다.

4. **YouTube API는 지금 붙이면 안 됩니다.** (아래 5장에서 자세히)
   특히 **"API 데이터로 새로운 점수/지표를 만드는 것"이 YouTube 개발자 정책상 기본적으로 금지**되어 있습니다. 우리가 하려는 "추천 점수" 같은 게 정확히 여기 걸립니다. 우회 방법은 있지만 조건이 붙습니다.

## 1. 현재 코드베이스 조사 결과

### 1-1. 완성된 것 (재사용 가능)

| 영역 | 상태 |
|---|---|
| 인증 (Google OAuth, 세션, 라우트 가드) | ✅ 완료, production 검증됨 |
| DB 6개 테이블 + RLS 21개 정책 + GRANT | ✅ 완료, 2계정 격리 테스트 통과 |
| 트리거 (profiles 자동생성, updated_at) + 인덱스 10개 | ✅ 완료 |
| TypeScript 타입 레이어 (`lib/types.ts`) | ✅ 완료 |
| 온보딩 5문항 → `channels` 저장 | ✅ 완료 (STEP 3) |
| 확립된 패턴 (Zod 검증 / Server Action / 에러 처리 / pending UI) | ✅ 완료 |
| Vercel 배포 파이프라인 | ✅ 완료 |

**결론: 방향을 바꿔도 지금까지 만든 것 중 버릴 것이 거의 없습니다.** 인증·DB·배포·패턴은 어떤 방향으로 가든 그대로 씁니다.

### 1-2. DB 스키마가 새 방향을 얼마나 받아주는가

기존 6개 테이블을 새 루프에 하나씩 대입해봤습니다.

| 새 방향에서 필요한 것 | 기존 테이블로 되는가 |
|---|---|
| 채널 정보 (누구에게 추천할지) | ✅ `channels` 그대로 |
| 추천된 영상 후보 | ✅ `video_ideas` 거의 그대로. `title`, `category`, `description`, **`reason`(추천 이유)** 컬럼이 이미 있습니다 |
| "이 영상으로 결정" | ✅ `content_projects.idea_id` — 이미 있고, partial unique index로 "아이디어 1개당 프로젝트 1개"까지 보장됨 |
| 제목/썸네일/영상구성 | ✅ `content_projects`의 `title_candidates`/`thumbnail`/`plan` jsonb |
| 촬영·편집 체크리스트 | ✅ `checklist_items` 그대로 |
| 업로드 상태 관리 | ✅ `content_projects.status` (IDEA→PLANNING→FILMING→EDITING→SCHEDULED→PUBLISHED) + `published_at` |
| AI 호출 기록 | ✅ `ai_generations` 그대로 |
| **추천 3개의 순위(1~3위)** | ⚠️ 없음 — 컬럼 추가 필요 |
| **한 번의 추천 묶음(3개 세트) 식별** | ⚠️ 없음 — 컬럼 추가 필요 |
| **업로드 후 성과 데이터** | ⚠️ 없음 — 테이블 추가 필요 (단, 나중 단계) |

**핵심 발견 1 — DB는 거의 그대로 씁니다.** 대규모 재작성이 필요 없습니다. 필요한 건 `video_ideas`에 컬럼 2~3개 추가하는 작은 마이그레이션 하나뿐입니다.

**핵심 발견 2 — "추천 → 프로젝트 전환율"은 이미 계산할 수 있습니다.**
`content_projects.idea_id`가 채워져 있으면 = 그 아이디어가 프로젝트로 전환된 것입니다. 별도 이벤트 추적 시스템(Amplitude, Mixpanel 등)을 붙이지 않아도, **이미 있는 두 테이블의 조인만으로 전환율이 나옵니다.** 다만 "추천 3개 세트 중 몇 개가 전환됐나"를 정확히 보려면 세트를 식별하는 컬럼이 필요합니다 (위의 ⚠️).

## 2. 경쟁 분석 — 무엇이 이미 상품화됐고 무엇이 남았나

### 2-1. 이미 상품화된 것 (= 차별점으로 쓰면 안 되는 것)

| 기능 | 누가 이미 하는가 |
|---|---|
| **AI가 다음 영상 추천 + 순위 + 이유** | **TubeBuddy "Next Video Ideas" (2026-07-22 출시)** — 순위와 근거 카드까지 동일. vidIQ는 "View Prediction" 점수로 수년째. |
| 아이디어 대량 생성 | vidIQ "Daily Ideas" — **하루 50개**, 월 1,500개 |
| 제목 / 썸네일 / 훅 / 개요 생성 | **YouTube Studio "Inspiration" 탭에서 전부 무료.** 프롬프트당 아이디어 9개 + 제목 + 썸네일 + 개요 + 훅 |
| 채널 분석 / 아웃라이어 리서치 | vidIQ, TubeBuddy, 그리고 **2026년 7월 YouTube가 "Research" 탭으로 직접 흡수 중** |
| "50개 말고 3개만" | UX 의견일 뿐, 경쟁사가 한 스프린트면 따라합니다 |

### 2-2. 한국어라는 방패 — 진짜지만 시한부입니다

- YouTube **Inspiration 탭은 영어 전용**입니다. 구글 공식 문서에 "이 도구는 영어로만 콘텐츠 아이디어를 제공한다"고 명시돼 있습니다.
- vidIQ도 자사 도움말에 "아이디어 기능은 영어 입력에 최적화되어 있으며 다른 언어에서는 성능이 떨어질 수 있다"고 인정합니다.
- TubeBuddy는 한국어 UI가 없습니다 (한국 랜딩 페이지조차 영어로 제공).

**그러나** — YouTube의 **"Ask Studio"는 한국어를 지원합니다.** 70개 이상 언어를 지원하고 한국어가 포함되어 있으며, 영상 컨셉 생성·개요 작성·대본 피드백까지 무료로 해줍니다.

→ 즉 **"한국어로 아이디어를 받는 것" 자체는 이미 무료로 가능합니다.** 한국어는 12~24개월 정도의 선점 우위이지 해자(moat)가 아닙니다. 이걸 유일한 차별점으로 삼으면 위험합니다.

### 2-3. 아무도 안 하는 것 (= 진짜 차별점)

1. **결정을 강제하는 것.** 모든 도구가 아이디어를 쏟아붓습니다(50개/9개/10개). **고르게 만드는 곳은 없습니다.** 0~1만 구독자 크리에이터의 진짜 병목이 "아이디어 부족"이 아니라 "결정 못 함"이라는 사장님의 진단은 리서치로 뒷받침됩니다.
2. **아이디어 → 프로젝트 상태 전환.** "저장된 아이디어" 목록은 어디에나 있지만, 저장된 아이디어가 **생명주기를 가진 제작 객체**로 바뀌는 곳은 없습니다.
3. **실행 레이어.** 촬영/편집/업로드 체크리스트를 다루는 건 Notion 템플릿뿐이고, 그건 채널 데이터와 전혀 연결돼 있지 않습니다.
4. **닫힌 루프.** vidIQ와 TubeBuddy는 사용자의 분석 데이터와 저장된 아이디어를 **둘 다 갖고 있으면서도 연결하지 않습니다.** 성과를 다음 추천에 반영하는 학습 장치가 없습니다.
5. **초보자용 콜드스타트.** 경쟁사 엔진은 전부 아웃라이어 분석 기반이라 데이터가 필요합니다. 구독자 200명 채널은 뻔한 결과만 받습니다. 데이터 0에서 시작하는 경로를 설계한 곳이 없습니다.

### 2-4. 왜 대기업이 우리를 안 따라올까 (= 방어 가능성의 근거)

이게 중요합니다. 위 1~4번이 기술적으로 어려워서 방어되는 게 아닙니다. **경쟁사에게 사업적으로 매력이 없어서** 방어됩니다.

- vidIQ는 **AI 크레딧**을 팝니다. 제작 관리는 크레딧을 소모하지 않아 과금 모델에 안 맞습니다.
- TubeBuddy는 **SEO 좌석과 브라우저 확장**을 팝니다. 제작 워크플로는 확장 프로그램 폼팩터에 안 맞습니다.
- YouTube는 **플랫폼 밖에서 무슨 일이 일어나는지 관심이 없습니다.** 크리에이터가 촬영을 끝냈는지 여부는 YouTube의 문제가 아닙니다.

→ 운영(ops) 레이어가 우리의 쐐기(wedge)입니다.

### 2-5. 한국 시장 — 기획 도구가 없습니다

조사한 한국 서비스는 전부 **분석/랭킹/인플루언서 마케팅**이었습니다.

- **블링(vling)** — 광고주↔크리에이터 매칭 마켓플레이스. 기획 기능 없음
- **녹스인플루언서** — 인플루언서 마케팅 분석. 마케터용
- **플레이보드** — 랭킹·수익 분석
- **뷰트랩(구 노아AI)** — 키워드/트렌드 리서치 + 강의. 가장 가깝지만 리서치+교육이지 제작 시스템은 아님 (사이트 접근이 막혀 현재 기능/가격 미확인)
- **Vrew** — 유일한 한국산 AI 영상 도구지만 **자막·편집(후반작업)**용

결정적 단서: 2025년 6월 TBWA 코리아 계열 매체의 "유튜브 기획~제작~SEO AI 툴" 가이드가 **기획 단계에는 ChatGPT와 Notion AI를 추천**합니다. 한국 크리에이터는 기획에 쓸 한국 도구가 없어서 범용 외국 도구를 쓰라는 안내를 받고 있습니다.

## 3. 사업 리스크 — 반드시 알고 가야 할 것

**0~1만 구독자는 유튜브에서 수익화가 가장 어려운 세그먼트입니다.** 본인들이 아직 돈을 못 벌고 있고, 대부분 중도 포기합니다(플랫폼 최고 이탈률). TubeBuddy가 공개한 자사 수치도, 아이디어 기능을 쓴 사용자의 **7일 내 유료 전환이 3.69%**입니다(안 쓴 사용자 0.34% 대비 10배지만, 절대값은 낮습니다).

이건 방향을 바꾸라는 뜻이 아니라, **"무료로 많이 모으고 나중에 과금"이 아니라 처음부터 "누가 왜 돈을 낼 것인가"를 같이 검증해야 한다**는 뜻입니다. 그리고 Spotter Studio 사례(1번 요약 참고)가 이걸 더 무겁게 만듭니다.

## 4. AI 추천 시스템 — 처음부터 복잡하게 만들지 않는 방법

리서치를 종합하면, 초기에 절대 하지 말아야 할 것은 **"추천 엔진"을 진짜로 만드는 것**입니다. 이유:

- 아웃라이어 분석/트렌드 점수는 YouTube API 데이터가 필요한데, 그게 정책 위반 위험이 있습니다(5장)
- 데이터가 없는 초보 채널에는 어차피 잘 작동하지 않습니다
- 만드는 데 오래 걸려서 "빨리 실제 사용자에게 보여주기"라는 목표와 정면 충돌합니다

**대신 이렇게 시작하는 것을 제안합니다 (3단계):**

**1단계 — LLM 한 번 호출로 끝내기 (MVP)**
입력: 온보딩 5문항 + (2회차부터) 지난 영상 성과 요약
출력: Zod 스키마로 검증된 추천 3개 (제목, 카테고리, **1~3위 순위**, **추천 이유**, 예상 난이도)
"엔진"이 아니라 **잘 설계된 프롬프트 하나**입니다. 이게 MVP에 충분합니다.

**2단계 — 규칙 기반 보정 (사용자 10명 이후)**
LLM 출력에 코드로 된 간단한 규칙을 얹습니다. 예: "지난번에 거절한 주제와 비슷하면 제외", "업로드 빈도 대비 제작 난이도가 높으면 순위 하향". LLM을 다시 부르지 않으므로 비용 0, 디버깅 쉬움.

**3단계 — 성과 피드백 반영 (데이터가 쌓인 뒤)**
사용자가 기록한 실제 성과를 다음 추천 프롬프트에 넣습니다. "이 채널은 A유형 영상이 B유형보다 3배 잘 됐다" 같은 요약을 코드로 계산해서 프롬프트에 문장으로 넣는 정도. 여기서도 머신러닝은 필요 없습니다.

**비용**: 추천 1회 = LLM 호출 1회입니다. 사용자 1명이 하루 한 번 추천받아도 호출량이 매우 적습니다. 정확한 단가는 제공자 가격 페이지에서 확인이 필요하지만(모델별로 다르고 자주 바뀝니다), **구조적으로 비용이 폭발할 수 없는 설계**라는 점이 중요합니다. 이미 결정하신 대로 **앱 안에 사용량 제한 코드를 넣지 않고 제공자 대시보드의 지출 상한**으로 막습니다.

## 5. YouTube API / 채널 데이터 / 성과 데이터 — 언제 붙일 것인가

여기가 이번 리서치에서 가장 중요한 기술 발견입니다.

### 5-1. 🔴 파생 지표(derived metrics) 금지 — 제품 컨셉에 직결

**YouTube API 서비스 개발자 정책** (최종 수정 2026-06-24) III.E.4.h 원문:

> API 클라이언트는 (i) API 데이터를 독립적으로 계산한 유사 데이터로 대체하거나, (ii) API 데이터를 사용해 **새롭거나 파생된 데이터 또는 지표를 만들어서는 안 됩니다.**

즉 **"바이럴 점수", "업로드 타이밍 점수", "트렌드 지수" 같은 걸 YouTube API 데이터로 계산하는 것이 기본적으로 금지**입니다. 우리가 하려던 "추천 점수"가 정확히 여기 해당합니다.

**빠져나갈 길 2가지:**
- **빠른 길**: 계산한 값을 원본 API 데이터와 **나란히** 보여주고, "이 수치는 YouTube가 제공한 것이 아니라 우리 서비스가 자체 계산한 것"이라는 **명확하고 눈에 띄는 고지**를 붙입니다. UI/문구 작업이라 비용이 거의 없습니다.
- **정식 길**: 감사(audit) 신청 시 "Analytics & Reporting" 용도를 선택해 파생 지표 허용 조항을 받습니다. 2026년 5~6월에 신설된 조항으로, 승인되면 자체 점수·순위·36개월 통계 보관까지 허용됩니다. 다만 **심사 기간이 공개돼 있지 않고 수개월 걸릴 수 있습니다.**

### 5-2. 🔴 검색 쿼터: 프로젝트 전체 하루 100회

2026년 6월 1일부터 쿼터 체계가 바뀌었습니다 (**인터넷의 대부분 자료가 아직 옛날 기준이라 틀립니다**).

| 버킷 | 하루 한도 |
|---|---|
| 일반 (`videos.list`, `channels.list`, `playlistItems.list` 등) | 10,000 유닛 (각 1유닛) |
| **`search.list` (검색)** | **하루 100회** — 별도 버킷 |
| `videos.insert` (업로드) | 하루 100회 |

**중요: 이 100회는 사용자 1명당이 아니라 우리 프로젝트 전체입니다.** 사용자가 10명만 돼도 키워드 검색 기능은 불가능합니다. 쿼터 증량은 감사(audit)를 통과해야 하고 기간이 공개돼 있지 않습니다.

반면 `videos.list`는 한 번에 ID 50개까지 조회 가능해서 실질적으로 넉넉합니다. **검색만 병목입니다.**

### 5-3. 🟡 노출수/CTR은 48시간 지연

- **일반 Analytics API로는 썸네일 노출수·CTR을 못 가져옵니다.** (거기 있는 `adImpressions`는 광고 노출로 전혀 다른 지표입니다)
- **2026년 1월 15일부터 Reporting API(대량 리포트)에서 가능해졌습니다** — `video_thumbnail_impressions`, `video_thumbnail_impressions_ctr`
- 단, 방식이 다릅니다: 작업(job)을 생성해야 리포트 생성이 시작되고, **첫 데이터가 나오기까지 최대 48시간**이 걸립니다. 대신 그 후 지난 30일치가 한꺼번에 채워집니다.
- 조회수·시청시간·평균 시청 지속시간·평균 시청 비율은 **연결 즉시 실시간**으로 가져올 수 있습니다.

### 5-4. 🟡 OAuth 인증 심사 — 생각보다 가볍습니다

좋은 소식입니다. YouTube 스코프(`yt-analytics.readonly`, `youtube.readonly`)는 **"민감(sensitive)"이지만 "제한(restricted)"은 아닙니다.** 구글의 제한 스코프 공식 목록에 YouTube 스코프가 하나도 없습니다.

→ **제3자 보안 감사(CASA), 감사 비용, 연간 재심사가 전부 필요 없습니다.**

필요한 것: 소유한 도메인(Search Console 인증) + **같은 도메인에 올린 개인정보처리방침** + 공개 홈페이지 + OAuth 동의 흐름을 보여주는 데모 영상. 비용 무료. 구글 공식 안내는 영업일 3~5일, 콘솔 FAQ는 10영업일. **실무적으로 2~3주 잡으면 됩니다.**

### 5-5. 🔴 그런데 "테스트 모드"에는 함정이 있습니다

OAuth 앱이 "Testing" 상태일 때:

| 항목 | 값 |
|---|---|
| 테스트 사용자 | 최대 100명 (수동 등록) |
| 경고 화면 | 표시됨 |
| **인증 만료** | **동의 후 7일** — 리프레시 토큰도 함께 만료 |

**이 7일 만료가 실제 제품에는 치명적입니다.** 사용자가 매주 다시 연결해야 합니다. 친한 크리에이터 몇 명 대상 비공개 베타에는 괜찮지만 그 이상은 안 됩니다.

"In production" 상태로 바꾸면 (심사 전이라도) 7일 만료는 사라지고, 대신 "확인되지 않은 앱" 경고를 본 사용자 **누적 100명** 상한이 걸립니다.

### 5-6. 데이터 보관 제한

- 사용자 **본인의 Analytics 데이터**: 필요한 기간만큼 보관 가능. 단 **30일마다 사용자가 여전히 접근을 허가하는지 재확인** 필요
- **공개 데이터(영상 제목/설명/썸네일 등)**: **30일 후 삭제 또는 갱신** 필요

→ 우리 서비스의 "채널 기억"은 합법적으로 유지 가능하지만, 캐시한 남의 영상 정보는 30일마다 만료시켜야 합니다.

### 5-7. ⚠️ Shorts 조회수 주의

2025년 3~6월에 Shorts 조회수 집계 방식이 바뀌었습니다(재생 시작만 해도 카운트). **2025년 중반을 걸치는 조회수 추이 그래프를 그리면 가짜 급등이 나타납니다.** 옛 기준이 필요하면 `engagedViews` 지표를 써야 합니다.

### 5-8. 결론: 언제 붙일 것인가

**MVP에서는 YouTube API를 붙이지 않는 것을 강하게 권합니다.** 이유:

붙이는 순간 이 문제가 전부 동시에 옵니다 — 파생 지표 금지 검토, 검색 쿼터 100회, 7일 토큰 만료, 도메인+개인정보처리방침+데모영상 준비, 2~3주 심사, 48시간 지연.

**MVP에서는 성과를 사용자가 직접 입력하게 합니다.** "지난 영상 조회수 몇이었나요?" 한 칸. 촌스러워 보이지만:
- 위 리스크가 **전부 사라집니다**
- 루프가 실제로 작동하는지를 **몇 주 안에** 검증할 수 있습니다
- 초보 유튜버는 영상 수가 적어서 손으로 입력하는 부담이 작습니다
- 나중에 API를 붙일 때 **입력 화면만 자동 채우기로 바꾸면 되고, 나머지 구조는 그대로**입니다

## 7. 정리 — 이 리서치가 바꾸는 것

1. **핵심 메시지를 "AI 추천"에서 "끝까지 가게 만드는 시스템"으로 옮겨야 합니다.** 추천은 입구일 뿐이고, 경쟁사가 이미 합니다.
2. **DB는 안 갈아엎어도 됩니다.** 작은 컬럼 추가 하나면 됩니다.
3. **YouTube API는 MVP에서 뺍니다.** 성과는 수동 입력.
4. **AI는 "엔진"이 아니라 "프롬프트 1개"로 시작합니다.**
5. **전환율은 이미 있는 테이블로 측정 가능합니다.**
6. **가장 큰 위험은 기술이 아니라 사업입니다** — Spotter 철수, 0~1만 세그먼트의 낮은 지불 의사.
