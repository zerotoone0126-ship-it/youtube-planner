# 리서치 — 편집본 AI 영상 분석

작성일: 2026-08-23
범위: 조사만. 코드 변경 없음.
관련 문서: `research-channel-manager.md`(법률·정책·경쟁), `plan-new-mvp.md`

> 이 문서의 벤치마크 수치 중 **[측정]** 표시가 있는 것은 실제로 FFmpeg 6.1.1을 2 vCPU 환경에서 돌려 얻은 값입니다. 나머지는 공식 가격 페이지 인용이거나, **[가정]**으로 명시했습니다. 확인 못 한 것은 9장에 따로 모았습니다.

## 1. 가장 중요한 결론 4가지

1. **말씀하신 예시("00:17~00:29 같은 화면이 오래 지속됨")는 Vision AI가 전혀 필요 없습니다.** FFmpeg의 `scdet` 필터가 샷 경계를 뽑아주면 샷 길이 분포에서 바로 나옵니다. [측정] 알려진 컷 29개 중 29개 검출.

2. **제안하신 `select='gt(scene,0.4)'`는 임계값이 잘못됐습니다.** [측정] 29개 중 23개만 검출(79%). FFmpeg 자체 기본값인 `scdet=t=10`은 29/29(100%)였습니다.

3. **가장 큰 비용은 AI가 아니라 스토리지 전송량(egress)입니다.** 30분 1080p 원본은 약 2.25GB이고, 이걸 워커로 내려받는 것만으로 **$0.2025**가 듭니다 — 전사(transcription) + 비전 + LLM을 **전부 합친 것보다 비쌉니다.** → **브라우저에서 미리 480p로 줄여 올리는 것이 이 시스템 전체에서 가장 중요한 비용 결정입니다.**

4. **Vercel에서는 못 돌립니다.** [측정 기반] 30분 영상 FFmpeg 처리 약 304초 > Vercel Hobby 함수 상한 300초. 게다가 요청 본문 상한이 4.5MB라 업로드가 Vercel을 통과할 수 없습니다.

**최종 비용: 비전 없이 영상당 $0.014~0.072 (5분→30분).** 선택적 비전을 넣으면 약 3배($0.043~0.228).

## 2. FFmpeg로 되는 것 [측정]

| 기능 | 필터 | 측정 결과 (6.5분 1080p 기준) |
|---|---|---|
| 메타데이터 | `ffprobe` | 0.08초 |
| 오디오 추출 | `-vn -ac 1 -ar 16000` | WAV 1.6초 / Opus 6.8초 |
| 프레임 샘플링 | `fps=1,scale=256:-2` | 15.2초 |
| **키프레임만 추출** | `-skip_frame nokey` | **2.0초 — `fps=1`보다 7.5배 빠름** |
| 장면 전환 | `scdet` | 16.9초, 29/29 검출 |
| 무음 구간 | `silencedetect` | — |
| 음량 (EBU R128) | `ebur128` | **100ms마다** 값 출력 → 공짜 에너지 타임라인 |
| 검은 화면 | `blackdetect` | — |
| **정지 화면** | `freezedetect` | 문서에 잘 안 알려진 필터. **정적인 샷을 직접 검출** |

### 2-1. 장면 검출 임계값 [측정]

| 방법 | 검출률 | 오탐 | 처리 시간 |
|---|---|---|---|
| `select='gt(scene,0.4)'` (제안하신 값) | **23/29 (79%)** | 0 | 13.9초 |
| `select='gt(scene,0.1)'` | 29/29 | 0 | 14.7초 |
| **`scdet=t=10` (기본값)** | **29/29** | 0 | 16.9초 |
| 먼저 축소 후 검출 | 29/29 | 0 | 52.8초 — **3.8배 느림** |

**의외의 결과 2개**: (a) 미리 해상도를 낮추면 오히려 **느려집니다**(스케일링 비용 > 절약되는 비교 비용). (b) `scdet`은 **모든 프레임의 점수**를 메타데이터로 출력해서, 살아남은 프레임만 주는 `select`보다 활용도가 높습니다.

⚠️ 테스트 영상이 단색 하드컷 합성본이라, 실제 핸드헬드 촬영 영상에서는 `t=10`이 오탐을 낼 수 있습니다. **실제 한국 유튜브 편집본 10개로 임계값을 튜닝해야 합니다.**

### 2-2. 더 정확한 도구가 필요하면

| 도구 | 특징 | 권장 |
|---|---|---|
| **FFmpeg `scdet`** | 하드컷만. 무료, 이미 파이프라인에 있음 | ✅ **여기서 시작** |
| **PySceneDetect `AdaptiveDetector`** | "카메라 움직임으로 인한 오탐을 완화"하도록 설계됨 | 오탐이 문제되면 여기로 |
| **TransNetV2** | F1 최고(BBC Planet Earth 96.2), **디졸브·페이드 같은 점진적 전환도 검출** | ❌ 유튜브 편집은 95%가 하드컷. GPU 비용 대비 이득 적음 |

### 2-3. 단일 패스로 묶으면 45% 빨라집니다 [측정]

| 방식 | 처리 시간 (388초 영상) |
|---|---|
| 따로따로 4번 실행 | 약 48초 |
| **한 번에 묶어 실행** | **26.2초** |

메타데이터·오디오·장면검출·프레임샘플링을 **FFmpeg 한 번의 호출**로 처리하십시오. 디코딩을 1번만 하기 때문입니다.

## 3. 🎯 Vision AI 없이 되는 것 — 비용 절감의 핵심

| 주고 싶은 피드백 | 필요한 신호 | 비전 필요? |
|---|---|---|
| "같은 화면이 오래 지속됨, 압축 고려" | `scdet` 샷 길이 분포 | **아니오** |
| "컷이 너무 빨라 따라가기 어려움" | 같은 샷 목록, 반대로 | **아니오** |
| "03:12에 어색한 공백" | `silencedetect` | **아니오** |
| "이 구간은 화면 변화가 없음 → B-roll 고려" | `freezedetect` / `mafd` 이동평균 | **아니오** |
| "소리가 너무 작음 (유튜브 기준 -14 LUFS)" | `ebur128` | **아니오** |
| "12:40에서 볼륨이 떨어짐" | `ebur128` 10Hz 타임라인 | **아니오** |
| "05:03에 의도치 않은 검은 화면" | `blackdetect` | **아니오** |
| "이 구간 말이 너무 빠름/느림" | 전사 단어 타임스탬프 → 분당 단어수 | **아니오** |
| "'그래서'를 40번 반복함" | 전사 텍스트 | **아니오** |
| "인트로가 훅까지 너무 오래 걸림" | 전사 + 샷 목록 + 초반 에너지 | **아니오** |
| "여기서 주제가 새고 있음" | 전사 → LLM | **아니오** |
| **"자막이 읽기 어려움 / 타이밍이 어긋남"** | 픽셀 필요 | **예** |
| **"B-roll이 말하는 내용과 안 맞음"** | 픽셀 + 전사 | **예** |
| **"프레이밍이 어긋남"** | 픽셀 | **예** |

**15개 중 11개 — 말씀하신 예시 포함 — 가 비전 비용 0으로 가능합니다.**

비전은 마지막 4개에만 필요합니다. 그것도 **균등 격자로 뽑지 말고, 값싼 신호가 이미 뭔가를 발견한 프레임에만** 돌리십시오(긴 샷의 중간 지점, mafd 급변 지점, 무음 경계). 이게 "중요 장면 선별" 단계의 올바른 구현입니다.

| 제공자 / 모델 | 시간당 | 한국어 | 단어 타임스탬프 |
|---|---|---|---|
| **Groq `whisper-large-v3-turbo`** | **$0.04** | 예 | ✅ |
| Groq `whisper-large-v3` | $0.111 | 예 | ✅ |
| AssemblyAI Universal-2 | $0.15 | ✅ | ✅ |

| **Deepgram Nova-3 multilingual** | $0.312 | ✅ `ko`, `ko-KR` | ✅ 기본 제공 |
| AssemblyAI Universal-3.5 Pro | $0.21 | ❌ **한국어 없음** (18개 언어) | — |
| 🔴 **OpenAI 전사 모델 전체** | $0.18~0.36 | 예 | ❌ **타임스탬프 없음** |

**두 가지 결정적 발견:**

🔴 **OpenAI는 탈락입니다.** 공식 문서: *"Use `whisper-1` when you need word or segment timestamps"* — 그런데 **`whisper-1`이 가격 페이지에서 사라졌습니다.** 현재 가격이 매겨진 OpenAI 전사 모델은 전부 타임스탬프를 못 줍니다. **우리 제품의 본질이 타임스탬프인데 말이죠.** (추가로 파일 25MB 상한)

🔴 **AssemblyAI 최신 모델은 한국어를 지원하지 않습니다.**

**권장: Groq `whisper-large-v3-turbo` ($0.04/시간).** Deepgram보다 7.8배 싸고 단어 타임스탬프를 줍니다. Deepgram은 한국어 품질이 실망스러울 때의 대안으로 남겨두십시오.

⚠️ **자체 호스팅**은 월 2,000시간을 넘어야 이득이고 GPU를 관리해야 합니다. MVP에서는 아닙니다.

## 5. Vision 모델 가격

이미지 1장의 토큰 비용:

| 제공자 | 계산식 | 256×144 프레임 |
|---|---|---|
| Gemini | 양변 ≤384px면 258토큰 | 258 |
| Claude | `ceil(w/28) × ceil(h/28)` | 60 |
| OpenAI | `ceil(w/32) × ceil(h/32)` × 계수 | 약 65 |

30분 영상 비전 비용 (10초에 1프레임 = 180장):

| 모델 | 비용 |
|---|---|
| `gemini-2.5-flash-lite` | $0.0046 |
| `gpt-5.6-luna` | $0.0023 |
| `claude-haiku-4.5` | $0.0108 |
| (1fps = 1800장, gemini-2.5-flash-lite) | $0.0464 |

**주목**: 가장 비싼 조합(30분, 1fps, Claude Haiku)도 **$0.11**입니다. "모든 프레임을 보내면 비용 폭발"이라는 우려는 **방향은 맞지만 실제 절감액은 4~10센트 수준**입니다. **전송량(egress)이 그보다 훨씬 큽니다. 프레임 선별을 과하게 최적화하지 마십시오.**

⚠️ **자막 읽기에는 해상도가 필요합니다.** 256×144로는 한국어 자막을 읽을 수 없습니다. 자막 분석을 할 거라면 512×288 이상이 필요합니다.

## 6. Gemini 네이티브 영상 입력 — 파이프라인 전체를 대체할 수 있는 선택지

공식 문서 기준:
- 모델이 영상을 **1 FPS로 샘플링** (변경 불가라고 명시)
- 기본 해상도 **프레임당 258토큰**, 저해상도 **66토큰**, **오디오 초당 32토큰**
- Files API: 파일당 2GB, 프로젝트당 20GB, **48시간 보관**

**30분 영상 = 522,000토큰 → `gemini-2.5-flash-lite` 기준 $0.052.** FFmpeg도, 전사 비용도, 프레임 선별 로직도 **전부 없이** 말이죠.

**약점**: 타임스탬프를 독립적으로 검증할 방법이 없습니다. 모델이 스스로 보고하는 값이고 1FPS 샘플링이라 정밀도가 ±1초입니다. **출력이 곧 타임스탬프인 제품에서는 무시할 수 없는 리스크**입니다. 이게 FFmpeg 기반 "정답"을 따로 두는 이유입니다.

**⚠️ 그리고 Gemini 무료 등급은 미공개 영상에 절대 쓰면 안 됩니다** (→ `research-channel-manager.md` 5-5장).

## 9. 권장 파이프라인

```
브라우저 (WebCodecs)
  └ 480p로 축소 재인코딩 → 프록시만 업로드 (8~10배 작아짐)
  └ 16kHz 모노 Opus 오디오 별도 추출·업로드
       ↓ Supabase로 직접 업로드 (Vercel 우회 — 4.5MB 상한)
Supabase Storage
       ↓
Cloud Run 작업 (무료 등급이 월 30분 영상 약 420개 커버)
  └ FFmpeg 단일 패스:
       scdet=t=10          → 샷 목록 + 프레임별 mafd
       -skip_frame nokey   → 공짜 키프레임 (fps=1보다 7.5배 빠름)
       ebur128 + silencedetect → 10Hz 음량·무음 타임라인
       blackdetect + freezedetect
  └ Groq whisper-large-v3-turbo → 전사 + 단어 타임스탬프
       ↓
  값싼 신호 규칙 엔진 (순수 CPU, $0)
    → 샷 길이 이상치 / 공백 / 정지 화면 / 음량 문제 / 발화 속도
    → 그리고 "비전을 볼 가치가 있는 20~40개 프레임"을 여기서 결정
       ↓
  선별된 프레임만 Vision (자막 분석 시 512×288 이상)
       ↓
  최종 LLM: 전사 + 샷 표 + 오디오 타임라인 + 규칙 플래그 + 비전 노트
    → 타임스탬프 기반 한국어 피드백
```

**제안하신 파이프라인에서 바꿀 3가지:**
1. **"중복 프레임 제거"를 별도 단계에서 삭제.** 프레임 선별은 값싼 신호(긴 샷, mafd 급변, 무음 경계)가 결정해야 합니다. 중복 제거는 4센트짜리 문제를 푸는 겁니다.
2. **"1fps 샘플링" → `-skip_frame nokey`.** 7.5배 빠르고, 키프레임은 이미 인코더가 "중요하다"고 판단한 프레임입니다.
3. **메타데이터·오디오·장면검출·프레임샘플링을 FFmpeg 한 번의 호출로.** 45% 빨라집니다.

## 10. 장르별 분석 기준 — 근거 등급을 나눠서

⚠️ **중요**: 온라인의 "유튜브 리텐션 조언" 90%는 출처 없는 민담입니다. 아래는 근거 강도를 4등급으로 나눴습니다. **제품 UI에서도 이 구분을 표시하는 것을 권합니다** — 그게 신뢰를 만듭니다.

### 등급 1 — YouTube 공식 문서

- 🎯 **"Intro" 지표 = 첫 30초 후에도 보고 있는 시청자 비율.** YouTube 자체 정의입니다. **훅 분석의 기준점은 3초도 8초도 아니라 0:30입니다.**
- YouTube 공식 리텐션 곡선 4가지 형태: **flat**(끝까지 시청) / **gradual decline**(점점 흥미 상실) / **spikes**(재시청·공유) / **dips**(이탈 또는 건너뜀). → **제품의 피드백 용어를 이 4개로 맞추십시오.** 크리에이터가 Studio에서 이미 보는 단어입니다.
- 🔴 **"최적 영상 길이는 없습니다."** 원문: *"There's no universal 'ideal' length for YouTube videos. It depends on your content, audience, and the video's purpose."* → **"8~12분이 좋다" 같은 규칙을 절대 코드에 넣지 마십시오.**
- Shorts 분류: 세로/정사각 + 3분 이하 + 2024-10-15 이후 업로드
- Shorts 공식 지표: **"Viewed vs. swiped away"**

### 등급 2 — 실제 데이터로 뒷받침됨

**Guo, Kim & Rubin (2014), ACM Learning@Scale** — 영상 862개, 학생 12.8만 명, 세션 690만 건:
- **영상 길이와 무관하게 시청 몰입은 약 6분에서 한계에 도달**
- 0~3분 영상: 세션의 75%가 3/4 지점 통과. **9분 초과: 절반도 못 감**
- 🎯 **발화 속도: 평균 156 wpm. 빠른 화자가 같은 길이 구간에서 약 2배의 몰입. 중간 속도(145~165 wpm)가 가장 몰입도가 낮았음** ← 반직관적이고 바로 써먹을 수 있음. **"천천히 말하라"는 정보형 콘텐츠에 나쁜 조언입니다.**
- 말하는 얼굴이 나오면 몰입도 상승 (46% vs 33%)
- 비싼 스튜디오 제작보다 **비격식·수제 느낌이 이김**
- ⚠️ 한계: MOOC 수학·과학 강의 데이터. 유튜브 예능에 그대로 일반화하면 안 됨

**Cutting, DeLong & Nothelfer (2010), Psychological Science** — 할리우드 영화 150편(1935~2005):
- 70년에 걸쳐 **샷 길이가 이웃 샷과 점점 더 상관되며 1/f 파워 스펙트럼에 접근** — 인간 주의력 변동과 같은 시간적 특징
- 🎯 **교훈은 "더 빨리 자르라"가 아닙니다. 샷 길이의 변화가 구조적이어야 한다는 것입니다.** 단조롭게 빠른 편집도 단조롭게 느린 편집만큼 실패입니다.
- ⚠️ 저자들 스스로 IMDb 평점과는 상관이 없었다고 밝힘. 구조 ≠ 품질

### 등급 3 — 신뢰할 만한 실무자의 관행 (데이터는 없음)

**유출된 MrBeast 제작 핸드북** — 플랫폼 최고 리텐션 조직의 실제 내부 문서:
- 🎯 **6,000만 명 중 2,100만 명을 첫 1분에 잃는 것이 "좋은" 결과로 취급됩니다.** 즉 **약 35% 첫 1분 이탈은 정상**입니다. → **정상적인 이탈에 대고 경고를 울리지 않도록 보정하는 데 매우 유용합니다.**
- 첫 60초의 임무는 단 하나: 주의를 잡고 썸네일의 약속이 지켜질 것을 증명
- 🎯 **1~3분 / 3~6분 / 6분~끝 각 구간에 별도의 임무를 정의** → 구간별 분석 UI의 좋은 템플릿

### 등급 4 — 근거 없는 민담 (규칙으로 넣지 말 것)

- ❌ "첫 3초가 전부" / "8초 훅" — 출처 없음. YouTube 공식 기준점은 **30초**
- ❌ "8~12분이 최적" — YouTube 공식 문서가 정면으로 부정
- ❌ "3초마다 컷" — Cutting 연구와 취지상 배치. 균일한 페이싱이야말로 실패 모드
- ❌ "좋은 리텐션은 50% 이상" — 벤더 발 수치이고 서로 모순됨. Retention Rabbit은 평균 23.7%라 하고 prepublish.ai는 35~75%가 좋다고 함
- ⚠️ **모든 "리텐션 벤치마크 리포트"는 벤더가 낸 것입니다.** 표본이 "리텐션 문제로 도구를 찾아온 크리에이터"라 편향돼 있습니다. **장르별 격차가 크다는 정성적 신호로만 쓰고, 숫자는 인용하지 마십시오.**

### 10-1. 드래프트하신 4개 장르 — 검토

**정보형** (근거가 가장 탄탄한 장르)
- 6분 미만 단위로 분절 (Guo, 실측)

- 말하는 얼굴이 오래 없으면 경고
- ⚠️ **드래프트에서 틀리기 쉬운 지점: "이해를 위해 천천히"는 데이터가 정반대를 말합니다**

**게임**

- Cutting의 1/f 통찰이 특히 강하게 적용됩니다 — 끊기지 않는 긴 플레이 구간이 샷 길이 스펙트럼을 평탄하게 만듭니다

- 두 번째 실패: 재훅 부재. 긴 스토리는 고조 지점이 필요하고, 없으면 곡선이 gradual decline 모양이 됩니다
- ⚠️ **드래프트에서 틀리기 쉬운 지점: "빨리 본론으로"를 모든 장르에 적용하는 것. 썰에서는 페이오프를 제대로 지연시키는 게 기술입니다. 이 장르는 규칙을 뒤집어야 합니다**

- 실패 모드: 첫 30초에 프레임 없음, 선별 없이 시간순 나열, 이동 장면을 통째로 남김, 앰비언트 사운드 방치, 지나치게 긴 원테이크
- 🎯 **"이 구간을 압축하세요"라는 조언이 가장 유용하고 가장 필요한 장르입니다. 시작 장르로 가장 좋습니다.**

### 10-3. 쇼츠는 완전히 별개 모드입니다

파라미터 조정이 아니라 다른 제품 화면입니다.

1. **YouTube 자체가 다른 객체로 취급합니다** (분류 규칙·피드·수익 풀·분석 용어 전부 다름)
2. **성공 지표가 근본적으로 다릅니다.** 롱폼은 리텐션 곡선 + 30초 체크포인트. 쇼츠는 **"Viewed vs swiped away"** — 첫 1~2초의 거의 이진 판단. **20초 영상에 "30초 인트로" 개념은 존재하지 않습니다**
3. **루프는 롱폼에 없는 개념입니다** — 마지막 프레임이 첫 프레임으로 이어지는가
4. 🎯 **쇼츠는 공간 분석이 필요합니다** — 자막과 핵심 요소가 UI 오버레이 영역(하단 캡션/CTA, 우측 액션 레일)을 피해야 합니다. **타이밍이 아니라 레이아웃 체크입니다. 값싸게 검증 가능하고, 조사한 범위에서 아무도 안 하고 있습니다**

⚠️ **YouTube는 쇼츠의 훅·루프·첫 몇 초에 대해 공식 가이드를 전혀 내지 않았습니다.** 쇼츠에 대해 하는 말은 전부 등급 3입니다. UI에서 그렇게 밝히십시오.

### 10-4. 🎯 한국식 자막 — 가장 강한 차별점

`research-channel-manager.md` 3-1장에 전체 근거를 정리했습니다. 요약:

- 한국 예능은 프로그램당 **제3자 자막 약 1,000개**, 미국은 **0개** (Hyeri Jung, 2016)
- 기본 정보 자막: 한국 약 700개 vs 미국 약 100개
- 한국 실무 분류 4종: **대사 / 상황 / 보조 / 설명 자막**
- 현재 트렌드: 괄호 자막 + 모션 트래킹을 채널 시그니처로

**분석 가능한 축**: 자막 밀도(분당 개수), 자막 공백 구간, 유형 배분, 가독성(크기·대비·표시 시간), 발화 대비 지연.

**서구 경쟁 4개사는 이 축이 존재한다는 것조차 모릅니다.** 그리고 기술적으로도 의미론적 페이싱 판단보다 쉽습니다.
