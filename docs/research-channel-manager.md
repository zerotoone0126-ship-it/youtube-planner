## 0. 먼저 — 제가 이전에 드린 정보 중 틀린 것을 정정합니다

지난 `research-product-pivot.md`에서 YouTube 파생 지표(derived metrics) 금지 조항에 대해 이렇게 썼습니다:

> "**빠른 길**: 계산한 값을 원본 API 데이터와 나란히 보여주고, '우리가 자체 계산한 것'이라는 고지를 붙입니다. UI/문구 작업이라 비용이 거의 없습니다."

**이 해석은 틀렸습니다.** 정책 원문을 다시 정확히 읽으면 III.E.4.h는 이렇게 구성돼 있습니다:

> "Your API Clients must not (i) replace API Data with similar, independently calculated data, or (ii) access or use API Data to create new or derived data or metrics. **To the extent your API Clients display any information, data or metrics not based on API Data alongside API Data**, your API Clients must include a clear and prominent disclosure there that such information, data and metrics are not from YouTube and are part of your own product."

두 번째 문장은 **"API 데이터에 기반하지 않은(not based on API Data)" 자체 데이터**를 API 데이터 옆에 보여줄 때의 **표시 의무**입니다. API 데이터로 계산한 값을 고지만 하면 허용된다는 뜻이 **아닙니다.** 즉 "고지하면 된다"는 탈출구는 존재하지 않습니다.

**실제 탈출구는 감사(audit) 승인 하나뿐입니다.** [Derived Metrics 정책 페이지](https://developers.google.com/youtube/terms/derived-metrics-policy)(최종 수정 2026-06-01)가 별도로 존재하며, 승인된 애널리틱스 용도의 개발자에게 다음을 허용합니다:

> "You may calculate and assign custom 'scores' to channels based on independently calculated averages, sums, or ratios of API Data."
> "Policy III E.4.b, E.4.c, and E.4.d are amended to allow accepted API Clients to store metrics … for up to 36 calendar months."

단, 이건 **감사 신청 후 승인을 받아야** 적용되는 개정 조항입니다. 승인 전에는 적용되지 않습니다. 심사 기간은 공개돼 있지 않습니다.

죄송합니다. 이 정정이 이번 리서치에서 가장 중요한 내용 중 하나입니다.

## 1. 🔴 "Reference Video 분석" 기능은 현재 설계로는 만들 수 없습니다

요청하신 기능은 이랬습니다:

> 사용자 장르에 맞는 공개 YouTube 영상 ~20개를 찾아 반복되는 구조적 패턴(첫 사건까지 걸리는 시간, intro 구조, 영상 길이, 장면 전환 패턴 등)을 일반화해서 보여준다.

**서로 독립적인 세 조항이 각각 이 기능을 막습니다. 하나를 우회해도 나머지가 남습니다.**

### 1-1. 영상 다운로드·디코딩 금지 (가장 명확한 벽)

개발자 정책 원문:

> "You and your API Clients must not, and must not encourage, enable, or require others to: **download, import, backup, cache, or store copies of YouTube audiovisual content without YouTube's prior written approval.**"

API 이용약관 §16.3:

> "no rights or licenses are granted to reproduce or distribute audiovisual content or make audiovisual content available in any manner other than through the use of the YouTube API Services."

**결과**: 남의 YouTube 영상에서 프레임이나 오디오를 추출해 "첫 사건까지 걸리는 시간", "장면 전환 패턴", "intro 구조"를 계산하는 **합법적 방법이 없습니다.** yt-dlp도, 헤드리스 브라우저 캡처도, 임베드 플레이어 스트림 가로채기도 전부 해당됩니다. "cache"와 "store copies"가 명시돼 있어서 서버에서 잠깐 디코딩만 하는 것도 조문상 안전하지 않습니다.

그리고 이 금지는 **"encourage, enable, or require others to"**까지 포함합니다. → **사용자에게 "경쟁 영상을 직접 다운받아 올려주세요"라고 안내하는 우회도 막힙니다.**

### 1-2. 채널 간 데이터 집계 금지 (III.E.2)

> "Do not aggregate API Data except that you may only aggregate API Data relating to YouTube channels that are under the same content owner as recognized by YouTube pursuant to content licensing agreement(s) between YouTube and such content owner. Such aggregated API Data must only be viewable by that content owner."

서로 무관한 20개 채널의 데이터를 모아 평균을 내고, 그걸 그 채널 주인이 아닌 우리 사용자에게 보여주는 것 — 이 예외 조항에 해당하지 않습니다.

⚠️ **미해결 지점**: Derived Metrics 정책은 "leaderboards"와 채널 비교를 허용한다고 하면서도 III.E.2를 명시적으로 개정한다고 쓰여 있지 않습니다. 즉 감사를 통과하면 채널 간 집계가 열리는지가 **문서상 불분명합니다.** 이건 변호사 또는 Google에 직접 물어야 할 항목입니다.

### 1-3. 30일 보관 한도

- **Non-Authorized Data**(다른 사람의 공개 영상 데이터): "limited amounts", **최대 30일**
- 30일 후 삭제 또는 갱신 필수

→ "장르별 레퍼런스 데이터베이스를 계속 쌓아간다"는 구조 자체가 승인 전에는 불가능합니다.

### 1-4. 그 외 지켜야 할 것들

- **제품 이름에 "YouTube", "YT", "You-Tube" 등을 쓸 수 없습니다.** ("YouTube를 위한 OO"라는 설명은 가능) → **현재 프로젝트명 "YouTube Planner"는 그대로 출시할 수 없습니다.**
- YouTube 임베드 플레이어 **위에 어떤 오버레이도 그릴 수 없습니다.** → 레퍼런스 영상 위에 타임라인 마커를 그리는 UI는 불가능
- YouTube 로고 사용 시 클릭하면 YouTube로 가야 함
- 사용자 데이터 삭제 요청은 **7일 이내** 처리 필수

## 3. 진짜 차별점은 무엇인가 — 이번 리서치의 핵심 발견

### 3-1. 🎯 한국식 자막(예능 자막) 분석

이게 이번 조사에서 나온 가장 강력한 발견입니다.

**한국 영상 편집의 자막 관행은 스타일 선호가 아니라 학술적으로 문서화된, 구조적으로 다른 편집 문법입니다.**

Hyeri Jung(2016), *Subtitles in South Korean Entertainment Television* 연구:

- 한국 예능 프로그램은 **"제3자 자막(third-party subtitles)"을 프로그램당 약 1,000개** 사용합니다. **미국 예능은 0개입니다.**
- 기본 정보 자막: **한국 약 700개 vs 미국 약 100개**
- 1990년대 중반 한국 제작진이 자막을 "정보 전달 도구"에서 **"창작·편집 장치"**로 재정의하면서 시작됐습니다.
- 2009년 방송통신심의위원회가 부적절한 자막을 규제하며 사회적 논쟁이 됐을 정도로 문화적으로 중심적입니다.

한국 업계의 실무 분류(고구마팜):
1. **대사 자막** — 발화 그대로
2. **상황 자막** — 장면 맥락
3. **보조 자막** — 감정·행동 묘사 (예능의 시그니처)
4. **설명 자막** — 정보 + 그래픽

**왜 이게 결정적인가:**

한국 YouTube는 이 문법을 방송 예능에서 그대로 물려받았습니다. **한국 크리에이터의 편집은 상당 부분이 자막 결정(밀도·타이밍·서체 감정·모션 트래킹)으로 구성됩니다.**

그런데 서구 경쟁사(아래 3-2 참고)는 전부 **샷 길이, 페이싱, 훅, 오디오만 분석합니다. 이 축이 존재한다는 것조차 모릅니다.**

그리고 기술적으로도 유리합니다 — **자막 검출·타이밍 분석은 "이 장면이 지루한가"라는 의미론적 판단보다 훨씬 쉽습니다.**

또한 Vrew가 120만 사용자로 한국 자동 자막 시장을 장악했다는 사실은 **한국에서 자막 도구 수요가 거대하다는 것을 이미 증명합니다.**

### 3-2. 🔴 그런데 "편집본 업로드 → 타임스탬프 피드백" 자체는 이미 있습니다

이건 반드시 아셔야 합니다. 영어권에는 **이미 4개 제품이 거의 같은 걸 합니다.**

| 제품 | 하는 일 | 가격 |
|---|---|---|
| **PreViral.ai** | MP4/MOV 업로드 → "매 프레임을 보고 타임스탬프 리포트" → 0~100 바이럴 점수 + 수정 후 예상 점수 | Free 1개/월 · $9 · $29 · $59 |
| **Retti.ai** | **"Editing Lab" — 게시 전 러프컷 업로드 → 타임스탬프 편집 노트**. 게시 전 리텐션 곡선 예측 주장 | Free 1회 · $30/월(연간) · $49/월 |
| **Retention Rabbit** | "97.7% 정확한 리텐션 예측" 주장, 약 3분 소요, **40개 이상 언어** | 미공개 |
| **Satura AI "Virality Lab"** | 파일 업로드 → 순위·타임코드 제안. **"실제 시청자 행동을 예측하지 않는다"고 명시** | 미공개 |

**하지만 넷 다 규모가 매우 작습니다.** 투자 발표 없음, Product Hunt 성과 없음, G2 없음, 커뮤니티 언급 거의 없음, 독립 리뷰 없음. 가격이 $9~59에 몰려 있다는 건 **아무도 가격 결정력을 못 찾았다는 신호**입니다. Retti의 외부 흔적은 창업자 개인 X 계정이 전부입니다.

**그리고 기술 해자가 사실상 0입니다.** Gemini API가 MP4를 받아 `MM:SS` 형식으로 타임스탬프 분석을 그냥 돌려줍니다. 15분 영상 저해상도 기준 약 12만 토큰 — 몇 센트입니다.

**한국어로는 아무도 안 합니다.** 넷 중 어느 곳도 한국어를 지원한다고 밝히지 않습니다(Retention Rabbit의 "40+ 언어"만 가능성 있음).

### 3-3. 🔴 "리텐션 예측"은 함정입니다

모두가 주장하고(Retti "AI 리텐션 곡선", Retention Rabbit "97.7% 정확"), **아무도 검증 결과를 공개하지 않았습니다.** Retention Rabbit의 97.7%는 방법론도 표본도 제3자 검증도 없는 벤더 마케팅 문구입니다.

유일하게 정직한 Satura는 **"예측이 아니라 기획 신호(candidate planning signals)"**라고 명시적으로 선을 긋습니다.

**틀린 리텐션 예측은 예측이 없는 것보다 나쁩니다.** 크리에이터가 그걸 믿고 재편집 → 게시 → 다른 곡선 확인 → 즉시 이탈. **Satura의 정직한 프레이밍을 채택하고 "진단 품질"로 경쟁하는 것을 강력히 권합니다.**

### 3-4. YouTube가 직접 만들 가능성

YouTube에는 재료가 전부 있습니다 — 영상, 실제 리텐션 정답 데이터, Gemini. 아직 안 만든 이유는 게시 전 리텐션 예측이 어뷰징과 크리에이터 반발을 부르기 때문일 수 있습니다. **5년이 아니라 12~24개월로 보는 게 안전합니다.**

## 5. 사용자가 올린 영상의 개인정보 문제

### 5-1. 얼굴·목소리가 담긴 영상 = 개인정보 (맞습니다)

개인정보보호법 제2조 제1호는 "사진"으로 식별되는 정보를 개인정보로 정의합니다. **본인의 정보라도 우리가 처리하면 우리가 개인정보처리자입니다.**

### 5-2. 민감정보(생체인식정보)인가 — 아마 아닙니다. 단 조건부

개인정보보호위원회 생체정보 가이드라인(2021-09-08)은 **목적**으로 구분합니다:
- **본인 인증·식별 목적** → 생체인식정보, 민감정보 규제(별도 동의 + 암호화)
- **특성 파악 목적(연령·성별·감정 등)** → 일반 생체정보

우리의 페이싱·컷·구조 분석은 **특성 파악**이므로 민감정보 규제가 발동하지 않아야 합니다.

🔴 **단, 다음을 추가하는 순간 민감정보로 넘어갑니다: 얼굴 인식, "같은 크리에이터인지 매칭", 음성으로 화자 식별.** 절대 넣지 마십시오.

### 5-3. 영상정보처리기기(제25조/제25조의2) — 해당 없음

이 조항들은 **카메라를 설치·운영하는 자**의 의무입니다. 우리는 카메라를 운영하지 않고 사용자가 스스로 찍어 올린 파일을 받을 뿐입니다. (변호사 1줄 확인 권장)

### 5-4. 🔴 국외 이전 — 미국 AI API로 영상을 보낼 때

2023년 개정으로 제28조의8이 **4가지 근거**를 둡니다:
1. 별도 동의
2. 법률·조약
3. **계약 이행에 필요한 위탁·보관 + 개인정보처리방침에 고지**
4. 개인정보위 인증 또는 적정성 인정 국가 (**미국은 아님**. EU는 2025-09-03 인정)

**우리 경우는 3번이 정석입니다** — 사용자가 돈 내고 요청한 분석을 하기 위한 위탁.

단, **개인정보처리방침에 아래를 수신자별로 전부** 적어야 합니다. "제3자 AI 서비스를 이용할 수 있습니다" 같은 문구로는 **불충분합니다**:

- 이전되는 개인정보 **항목** (영상 파일, 얼굴 이미지, 음성 포함)
- 이전되는 **국가** (미국), 이전 **일시 및 방법**
- 수신자 **명칭과 연락처** (OpenAI / Anthropic / Google 실명)
- 수신자의 **이용 목적**, **보유·이용 기간**
- **거부 방법·절차 및 거부의 효과**

### 5-5. 🔴 AI 제공자 약관 — Gemini 무료 등급은 절대 금지

미공개 영상을 다루므로 이게 매우 중요합니다.

| 제공자 | 학습 사용 | 보관 | ZDR |
|---|---|---|---|
| **OpenAI** | 계약상 "Customer explicitly agrees" 없으면 학습 안 함 | 남용 모니터링 30일 | 있음(사전 승인 필요). stateful 엔드포인트 제외 |
| **Anthropic** | "Anthropic may not train models on Customer Content" | 30일 자동 삭제. ⚠️ **안전 시스템에 플래그되면 최대 2년, 분류 점수는 7년** | 있음(승인 필요) |

## 6. 어뷰징 방지 (Stripe 문서 기반)

가장 효과적인 순서:

1. **체험 시작에 카드 등록 요구** — 비싼 연산 기능에서 가장 강력한 단일 통제
2. **서버에서 하드 캡** — 계정별/일별/영상 분 단위. 요청 수가 아니라 **총 업로드 분(minutes)**을 제한
3. 일회용 이메일 도메인 차단
4. 기기 지문 + IP 가입 속도 모니터링
5. "UI를 안 거치고 바로 비싼 엔드포인트를 호출하는" 패턴 감시
6. **2~4주는 관찰만 하고 차단하지 않기** (진짜 초보를 막지 않기 위해)

⚠️ 기기 지문·IP 로깅은 전부 개인정보 처리라 개인정보처리방침에 고지해야 합니다. **휴대폰 본인확인은 본인확인기관 계약이 필요하니 직접 만들지 마십시오.**
