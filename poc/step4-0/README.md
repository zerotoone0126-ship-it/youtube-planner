# STEP 4-0 PoC 준비 폴더

이 폴더는 production 코드(Next.js 앱, DB, 기존 dependency)와 완전히 분리된 격리 공간입니다. 여기 있는 모든 것은 실험용이며, production 저장소나 사용자 컴퓨터의 프로젝트 폴더에는 반영되지 않습니다.

## 환경 점검 결과 (중요 — STT/OCR 방식 재확인 필요)

이 클라우드 작업환경의 네트워크는 패키지 레지스트리(pypi/npm 등)로만 열려 있고, 일반 인터넷 접근이 막혀 있습니다. 확인 결과:

- Whisper(faster-whisper/openai-whisper)가 모델 가중치를 받아오는 huggingface.co, openaipublic.azureedge.net → **접근 불가**
- PaddleOCR가 모델을 받아오는 bcebos.com(Baidu) → **접근 불가**
- Tesseract 한국어 언어팩(tessdata, GitHub raw) → **접근 불가** (영어 언어팩만 이미 설치되어 있음)
- 사용자 컴퓨터에서 직접 셸 명령을 실행하는 도구는 이번 세션에 연결되어 있지 않음

즉 애초에 승인받은 "오픈소스 로컬 모델" 방식은 STT와 (외부 모델을 새로 받아야 하는) OCR 엔진 모두 이 환경에서 그대로 실행할 수 없습니다. 아래 두 가지로 대체합니다.

- **OCR(burned-in 자막 탐지)**: 외부 OCR 서비스/모델 없이, 프레임 이미지를 Claude(저)가 직접 시각적으로 읽어 자막 텍스트와 구간을 판독하는 방식으로 대체합니다. FFmpeg로 프레임을 추출하는 것은 네트워크가 필요 없어 문제없이 가능합니다. 이 방식은 상용 OCR API/오픈소스 OCR 모델과 기술적으로 다른 방식이라는 점을 최종 보고서에 명시하겠습니다(정확도 참고치로는 유효하지만, production에 그대로 쓸 기술은 아닙니다).
- **STT(한국어 음성 인식)**: 로컬 실행이 막혀 있어 대체 수단이 없습니다. 상용 API 키(예: Groq) 없이는 STT 정확도 항목을 이번 PoC에서 측정할 수 없습니다 — 이 부분은 별도로 확인 필요합니다.
- FFmpeg 기반 항목(무음/음량/블랙프레임/씬체인지/정적구간 신호)은 전부 로컬 실행 가능하며 영향 없습니다.

## 폴더 구조

```
poc/step4-0/
  videos/         # 사용자가 제공할 테스트 영상 원본 (이 스크래치 폴더 밖으로 나가지 않음)
  ground-truth/   # 사람이 직접 라벨링한 정답 데이터 (CSV 템플릿 4종)
  scripts/        # 실험용 임시 스크립트 (production 의존성 트리에 추가되지 않음)
  results/        # 예측 결과, 채점 결과, 최종 리포트 초안
```

## 촬영/제작 체크리스트

### 정확도 테스트용 (3~10분 샘플)
- 게임 3개, 스토리·썰 3개, 정보형 3개 (총 9개)
- 자막 스타일이 아래 6가지를 가능한 한 골고루 포함하도록 배치 (한 영상에 여러 스타일이 섞여도 됩니다):
  1. 일반 하단 자막
  2. 컬러 자막
  3. 테두리/그림자 자막
  4. 큰 강조 자막
  5. 화면 중앙 또는 상단 자막
  6. 짧게 등장하는 예능식 자막
- 각 영상에는 실제 편집 컷이 여러 번 있어야 하고(컷 감지 평가용), 의도적으로 지루한/정적인 구간도 최소 1곳 포함되면 좋습니다(정적구간 평가용).

### 처리시간/비용 테스트용 (별도)
- 5분 1개, 10분 1개, 20~30분 1개 — 장르는 무관, 위 9개 중 하나를 재사용해도 됩니다.

### 파일 전달 방법
- 대화창에 직접 업로드하거나, 연결된 컴퓨터 폴더 경로를 알려주시면 제가 스테이징해서 가져오겠습니다.
- 파일명 규칙(선택): `{genre}_{번호}.mp4` (예: `game_01.mp4`, `story_02.mp4`, `info_03.mp4`) — 아래 ground-truth 템플릿의 `video_id`와 맞추면 채점이 수월합니다.

## Ground truth 라벨링 방법

`ground-truth/` 폴더의 CSV 템플릿 4종을 영상별로 채워주시면 됩니다. 스프레드시트(Excel/Google Sheets)로 열어서 작성하셔도 되고, 그대로 CSV로 편집하셔도 됩니다.

1. `stt-ground-truth-template.csv` — 들리는 대사를 그대로 받아쓰고 시작/종료 시각(초) 기록. 영상 전체가 아니라 무작위로 고른 30~50개 발화 구간만 해도 됩니다.
2. `subtitle-ground-truth-template.csv` — 화면에 자막이 보이는 구간의 시작/종료 시각, 그 자막의 전체 텍스트, 스타일 태그(위 6종 중 하나)를 기록.
3. `cut-ground-truth-template.csv` — 실제 편집 컷이 일어나는 모든 시점(초)을 기록.
4. `static-ground-truth-template.csv` — "지루하다"고 느껴지는 정적 구간의 시작/종료 시각을 기록. 가능하면 본인 외 1명이 더 독립적으로 표시해 주시면(같은 파일에 `labeler_id`를 다르게 해서 추가) 겹치는 구간만 정답으로 채택하는 방식을 쓸 수 있어 더 엄밀해집니다. 혼자 하셔도 진행은 가능하며, 그 경우 "단일 라벨러"라는 한계를 최종 보고서에 명시하겠습니다.

라벨링에 걸리는 시간은 영상 재생시간의 3~5배 정도로 예상됩니다(직접 해보시면서 조정하셔도 됩니다). 전부 한 번에 다 하지 않고 일부 영상만 먼저 라벨링해서 보내주셔도 그것부터 진행할 수 있습니다.
