# 스모크 테스트 결과 (도구 검증용 — 정확도 결과 아님)

이 문서는 실제 영상/정답 데이터가 없는 상태에서 **파이프라인 코드 자체가 정상 동작하는지**만 확인한 기록입니다. 여기 적힌 어떤 숫자도 STEP 4-0의 실제 판정 근거로 쓰지 않습니다 — 합성으로 만든 21초짜리 테스트 클립(단색 화면 전환 + 사인파 톤 + 무음 구간 + 검은 화면 구간 + drawtext로 넣은 가짜 한국어 자막) 하나에서 나온 결과일 뿐입니다.

## 확인된 것

1. **FFmpeg 단일 패스 결합 추출**(`silencedetect` + `blackdetect` + `freezedetect` + `scdet` + `signalstats` + `metadata=print`)이 정상 동작함을 확인했습니다. 21초 영상 처리에 약 1.3초 소요.
2. **중요한 버그를 발견하고 고쳤습니다**: `scdet` 필터는 기본적으로(또는 `threshold=8` 같은 "적당한" 값으로) 설정하면 실제 컷으로 판단한 프레임에서만 값을 출력하고, 나머지 프레임에서는 아무 값도 내보내지 않습니다. 원래 계획(연속적인 MAFD 값을 뽑아서 우리가 직접 threshold/persistence를 튜닝)대로 쓰려면 **`scdet=threshold=0:sc_pass=1`로 설정해야** 모든 프레임에서 값이 나옵니다 — 실제 컷 판단은 Python 스크립트(`detect_cuts.py`)에서 합니다. 이 내용은 `parse_continuous_signals.py`의 주석에 남겨뒀습니다.
3. 이벤트 파싱(`parse_events.py`), 연속 신호 파싱(`parse_continuous_signals.py`), 컷 후보 탐지(`detect_cuts.py`), 정적구간 탐지(`detect_low_motion.py`), 채점 스크립트(`score_points.py`) 모두 실행해봤고 버그 1건(정적구간 스크립트의 컬럼명 오타)을 발견해 고쳤습니다.
4. **자막 OCR 대체 방식(Claude가 프레임 이미지를 직접 읽는 방식) 검증**: 프레임 추출 스크립트로 뽑은 이미지를 제가 직접 읽어 "한국어 자막 테스트"라는 삽입 텍스트를 정확히 읽어낼 수 있음을 확인했습니다. (참고: 이 클라우드 환경의 기본 `drawtext` 폰트는 한글 글리프가 없어 처음엔 빈 사각형(tofu)으로 렌더링됐고, Noto Sans CJK KR 폰트를 명시적으로 지정한 뒤에야 정상 렌더링됐습니다 — 이건 테스트 클립을 만드는 제 쪽 문제였고, 실제 사용자가 캡컷/프리미어 등으로 만든 진짜 자막 영상에는 해당하지 않습니다.)
5. **주의할 점(합성 클립의 한계, 실제 영상 검증 필요)**: 단색→단색 전환(초록→빨강) 구간에서 `scd.mafd`가 0으로 나온 사례를 발견했습니다. Y(휘도) 채널 차이가 우연히 작았던 것으로 보이며, 실제 텍스처가 있는 영상에서도 이런 사각지대가 있는지는 실제 영상으로 확인이 필요합니다 — 이번 발견은 "단일 색상 배경"이라는 비현실적인 합성 클립의 특성일 가능성이 높습니다.
6. 프레임 차분 기반 사전 필터(`extract_frames.py`)가 화면 전체 평균 차분만 보기 때문에, 화면의 작은 영역에만 나타나는 자막 텍스트 등장/소멸을 놓칠 수 있다는 것도 이번 테스트에서 드러났습니다 — 실제 자막 탐지 단계에서는 자막이 나올 만한 영역(하단/중앙 등)에 가중치를 준 차분 방식으로 보완이 필요해 보입니다. STEP 4-0 실제 실행 시 반영하겠습니다.

## 확인되지 않은 것 (여전히 필요)

- 실제 정확도/재현율/CER 수치 — 전부 진짜 영상 + 사람이 라벨링한 정답이 있어야 나옵니다.
- 한국어 STT — 환경 제약으로 이번 PoC에서 미검증 (아래 별도 계획 참고)
- 실제 게임/스토리·썰/정보형 영상에서의 장르별 차이
